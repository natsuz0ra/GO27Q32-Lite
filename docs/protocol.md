# 显示器控制边界

实现位于 `native/ControlHost/Core/Models.cs` 和 `native/ControlHost/Hardware`。界面不直接写 DDC，后端负责检查设备、范围、执行顺序和读回结果。

只允许唯一匹配 `GBT2761` 或 `GBT275C` 的目标设备写入。设备未连接、路径无效或参数不可读时，保留禁用状态。

部分功能采用厂商扩展控制码，不能直接替换为通用 MCCS 编号：

| 功能 | 控制码 | 已确认的值 |
| --- | --- | --- |
| Gamma | `0xE9` | `0` 关闭，`1` 1.8，`2` 2.0，`3` 2.2，`4` 2.4，`5` 2.6 |
| 准星 | `0xEF` | `0` 关闭，`1`～`4` 对应四种准星 |
| 输入源 | `0xF0` | `0` HDMI 1，`1` HDMI 2，`2` DisplayPort，`3` USB-C |

控制码和枚举曾与原厂安装包内的控制逻辑核对。项目仅发布独立实现，没有附带反编译产物或原厂二进制。

Windows HDR 使用 DisplayConfig 接口，按显示路径定位目标。系统 HDR 开关、当前实际输出和显示器机身的 HDR 专用预设是不同状态。

1.0.1 增加手动 HDR 预设切换。用户实测确认 `0xE7` 写入 `0`～`4` 依次对应 HDR显示、HDR游戏、HDR电影、HDR亮彩和 HDRPeak 1300。后端仅在 HDR 输出稳定、目标唯一时发送；1.0.2 起，手动 HDR 操作会先暂停应用规则，保留当前画面。不预读、不跳过相同请求、不以 E7 读回验证。写后重新枚举物理句柄。界面仅显示本次运行的“上次请求”，不声称已读出当前预设。

本机 HDR 读取不能直接用于当前画面参数：机身 HDR游戏亮度从 100 改为 99 时，`0x10` 仍读到 80；向 `0x10` 写入 99 后，读取变为 99，机身 HDR 亮度仍是 100。测试后已恢复写前读数 80。不能依据菜单位置或读回成功，推定其他 HDR 参数与 SDR 共用写入协议；本版本没有新增 HDR 参数控制。

1.0.3 适配预设切换的黑屏重连。SET 成功后不立即检查旧句柄：先等待 2 秒，再每隔 500 毫秒重新枚举同一设备、读取 Windows HDR 状态，连续三次可用才结束。首轮最多 24 次探测；仍未恢复时，交由后台继续观察。期间不查询 VCP，也不重发 SET。原目标路径改变时停止等待。恢复只确认连接与输出状态，不确认实际 HDR 预设。

增加控制项前，应确认型号、有效值、读回行为及 SDR/HDR 限制。自动测试中的模拟值不能替代实机验证。

1.0.4 将配置的 HDR 部分改为独立 `HdrPreset` 字段（空值保持当前，0～4 为明确请求）。旧 `HdrValues` 仅用于兼容、导出和用户手动复制，任何手动套用、自动规则、基线采集与恢复都不再读取或写入其中的常规参数。HDR 下拦截所有 SDR 画面参数写入，且不把对应 GetVCP 结果暴露为 HDR 当前值。

自动规则的 HDR 预设切换使用与手动操作相同的黑屏恢复流程。若启动时已经在 HDR 且规则会写预设，必须明确桌面默认返回策略；不能假装能恢复读不到的初始预设。恢复未确认时暂停规则，不立即重发或发送预设回滚。

1.0.6 修正 HDR 配置被整组忽略的回归。`HdrValues` 仅放行 `crosshair`、`refreshOverlay`、`freeSync` 和 `volume` 四项独立功能，常规画面参数继续保留但不执行。HDR 基线只采集这些已支持的独立功能，并仅采集一次；按应用切换时合并对应配置，退出后恢复。预设切换完成并确认连接稳定后，再应用独立功能。只修改独立功能的规则不要求指定 HDR 返回预设。
